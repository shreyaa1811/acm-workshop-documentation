# Day 2 : Ship an AI Meme Generator to Google Cloud

**What you'll build today:** a small web app (upload a photo → AI writes a caption → you get a meme) and take it all the way from your laptop to a **live public URL** on Google Cloud, then make it deploy itself with GitHub Actions.

## 1. What you need

- **Docker Desktop** running (the whale icon in your tray is steady, not animating)
- **Google Cloud CLI** (`gcloud`), **Git**, and **VS Code** installed — get the CLI from [cloud.google.com/sdk/docs/install](https://cloud.google.com/sdk/docs/install)
- A **Google Cloud account with billing turned on** (the free trial is fine; if you don't have one, pair up with someone who does)
- The workshop repo **cloned** to your machine — [the AI Meme Generator app](https://github.com/kalyani-2024/ai-meme-generator) (`git clone https://github.com/kalyani-2024/ai-meme-generator.git`)
- A free **Gemini API key** — you'll create it in the setup step below

Quick check that your tools are ready:

```bash
docker run hello-world      # Docker works
gcloud version              # Google Cloud CLI installed
git --version               # Git installed
```

## 2. Set your variables once

Your **project ID** must be **globally unique**, so add your initials and a few digits where you see the placeholders. Paste this block into your terminal at the start (every later command reuses it).

**PowerShell (Windows):**
```powershell
$PROJECT   = "meme-workshop-<yourinitials>-<4digits>"   # 6-30 chars: lowercase letters, digits, hyphens
$REGION    = "me-central1"
$REPO      = "meme-repo"
$SERVICE   = "meme-generator"
$IMAGE     = "ai-meme-generator"
$IMAGE_URI = "$REGION-docker.pkg.dev/$PROJECT/$REPO/${IMAGE}:v1"
```

**Bash (macOS / Linux / WSL):**
```bash
PROJECT="meme-workshop-<yourinitials>-<4digits>"
REGION="me-central1"; REPO="meme-repo"
SERVICE="meme-generator"; IMAGE="ai-meme-generator"
IMAGE_URI="$REGION-docker.pkg.dev/$PROJECT/$REPO/${IMAGE}:v1"
```

> If a command later fails, 90% of the time it's a typo in a name or a variable you forgot to set. Check here first. If you change `$PROJECT`, re-run the `$IMAGE_URI` line too.

## 3. Setup: your project and your AI key

### 3.1 Sign in and create today's project

```bash
gcloud auth login                       # sign in (opens your browser)
gcloud projects create $PROJECT         # if the ID is taken, change the digits
gcloud config set project $PROJECT

gcloud billing accounts list            # copy your ACCOUNT_ID
gcloud billing projects link $PROJECT --billing-account=<ACCOUNT_ID>

gcloud services enable run.googleapis.com artifactregistry.googleapis.com secretmanager.googleapis.com
```

> A **project** is a labelled box that holds everything you create today. Delete the box at the end and it all goes.

### 3.2 Get a free Gemini API key

1. Go to [aistudio.google.com](https://aistudio.google.com) and sign in.
2. Click **Get API key → Create API key**.
3. Copy the key and keep it somewhere safe for now. It's a **secret** (never paste it into code or Git).

> ⚠️ Keep the project AI Studio suggests for the key. **Don't** create it in your workshop project. That project has billing on, so Gemini calls there would be charged instead of free.

## 4. Containerize the app

### 4.1 Run it locally first (no Docker)

```bash
cd ai-meme-generator
pip install -r requirements.txt
python app.py
```

Open **http://localhost:8080**. The page loads and says "AI not configured yet" — that's expected, we haven't given it a key. Stop it with `Ctrl+C`.

> This only works because your laptop happens to have the right Python and packages installed. That's the "works on my machine" problem, which is exactly what a container fixes.

### 4.2 Write the Dockerfile

Create a file named **`Dockerfile`** (no extension) in the project folder.

```dockerfile
# Start from a small official Python image
FROM python:3.12-slim

# Work inside this folder in the image
WORKDIR /app

# Copy ONLY requirements first so this layer caches and installs don't re-run on every code change
COPY requirements.txt .

# RUN happens at BUILD time — installs packages into the image
RUN pip install --no-cache-dir -r requirements.txt

# Copy the rest of the app (code + fonts + samples)
COPY . .

# Document the port the app listens on
EXPOSE 8080

# CMD happens at CONTAINER START time — runs the app
CMD ["gunicorn", "--bind", "0.0.0.0:8080", "app:app"]
```

Key things to remember:
- **`RUN` vs `CMD`** : `RUN` runs while *building* the image (install stuff). `CMD` runs when the container *starts* (run the app).
- **Requirements copied before the code** : layers are cached top to bottom, so dependencies don't reinstall every time you tweak code.
- **No API key anywhere** : secrets never go inside the image. We add the key later, at run time.

### 4.3 Build the image

```bash
docker build -t ai-meme-generator:v1 .
```

> **On an Apple Silicon Mac (M1/M2/M3/M4)?** Use `docker build --platform linux/amd64 -t ai-meme-generator:v1 .` instead — Cloud Run needs `amd64` images.

Watch each instruction become a **layer**. Build again after a small edit and you'll see some layers say `CACHED`.

### 4.4 Run the container (with the API key)

Paste your Gemini key:

```powershell
# PowerShell
docker run -d -p 8080:8080 `
  -e GEMINI_API_KEY="<your-gemini-key>" `
  -e MEME_STYLE="classic" `
  ai-meme-generator:v1
```

```bash
# bash
docker run -d -p 8080:8080 \
  -e GEMINI_API_KEY="<your-gemini-key>" \
  -e MEME_STYLE="classic" \
  ai-meme-generator:v1
```

Open **http://localhost:8080**, upload a photo, click **Make Meme**. 

> `-p 8080:8080` means `host:container`. The `-e` flags inject config at run time (same image, different behaviour).

### 4.5 Useful container commands

```bash
docker ps                 # what's running (shows the container ID/name)
docker logs <container>   # see the app's logs
docker stop <container>   # stop it , containers are disposable
```

> Stop and start a fresh container and your meme is **gone**. Containers don't keep files. To save memes you'd use cloud storage (like Google Cloud Storage).

## 5. Push the image to Artifact Registry

### 5.1 Create the registry repository

```bash
gcloud artifacts repositories create $REPO `
  --repository-format=docker `
  --location=$REGION
```

*(Bash: swap the backtick line-breaks for `\`.)*

### 5.2 Log in, tag, and push

```bash
# Let Docker use your gcloud login for this registry (answer Y if asked)
gcloud auth configure-docker "$REGION-docker.pkg.dev"

# Tag the image so it points at YOUR registry (full name = region-host/project/repo/image:tag)
docker tag ${IMAGE}:v1 $IMAGE_URI

# Push it to the cloud
docker push $IMAGE_URI
```

> We use an explicit tag `:v1`, never `:latest` — so you always know exactly what's deployed.

### 5.3 See it in the console

Go to [console.cloud.google.com](https://console.cloud.google.com) (check your project is selected at the top) → **Artifact Registry → `meme-repo` → `ai-meme-generator`**. Your image is now sitting in the cloud.

## 6. Deploy to Cloud Run (the live URL)

### 6.1 First deploy (no key yet)

```bash
gcloud run deploy $SERVICE `
  --image $IMAGE_URI `
  --region $REGION `
  --port 8080 `
  --allow-unauthenticated `
  --set-env-vars "MEME_STYLE=classic"
```

> **Cloud Run** runs your container for you — no servers to set up. `--port 8080` tells it which port the app listens on (like `-p` in Docker). `--allow-unauthenticated` makes the URL public. When nobody's using it, it scales to zero and costs nothing.

It prints a **Service URL**. Open it and the page says "AI not configured yet". Let's fix that.

### 6.2 Store your AI key in Secret Manager

```powershell
# PowerShell
$GEMINI_KEY = "<your-gemini-key>"
$GEMINI_KEY | gcloud secrets create gemini-api-key --data-file=-

$PROJECT_NUMBER = gcloud projects describe $PROJECT --format="value(projectNumber)"
gcloud secrets add-iam-policy-binding gemini-api-key `
  --member="serviceAccount:$PROJECT_NUMBER-compute@developer.gserviceaccount.com" `
  --role="roles/secretmanager.secretAccessor"
```

```bash
# bash
GEMINI_KEY="<your-gemini-key>"
printf "%s" "$GEMINI_KEY" | gcloud secrets create gemini-api-key --data-file=-

PROJECT_NUMBER=$(gcloud projects describe $PROJECT --format="value(projectNumber)")
gcloud secrets add-iam-policy-binding gemini-api-key \
  --member="serviceAccount:$PROJECT_NUMBER-compute@developer.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"
```

> **Secret Manager** is a locked vault for secrets. The second command gives your Cloud Run app, and only your app permission to read this one secret.

### 6.3 Attach the secret to your app

```bash
gcloud run services update $SERVICE --region $REGION `
  --set-secrets "GEMINI_API_KEY=gemini-api-key:latest"
```

> Notice: the secret key was **never** in your Dockerfile, image, or Git. Cloud Run hands it to your app at run time.

### 6.4 Open your live app

```bash
gcloud run services describe $SERVICE --region $REGION --format="value(status.url)"
```

Open that URL, upload a photo, and make a meme. Now it's a real public website serving your container. 

> If the first load takes a few seconds, that's a **cold start**. Cloud Run starting your app up from zero.

### 6.5 Change the humor without rebuilding

```bash
gcloud run services update $SERVICE --region $REGION --update-env-vars "MEME_STYLE=sarcastic"
```

Make another meme - same image, funnier captions. Each change creates a new **revision**:

```bash
gcloud run revisions list --service $SERVICE --region $REGION
```

### 6.6 Handy Cloud Run commands

```bash
# see recent logs
gcloud run services logs read $SERVICE --region $REGION --limit 30

# limit how many copies can run (also caps your bill)
gcloud run services update $SERVICE --region $REGION --max-instances 3
```

In the console, explore **Cloud Run → `meme-generator`**: **Metrics** (requests and instance count), **Revisions**, **Logs**, and **Edit & deploy new revision → Variables & Secrets** (your key shows as a Secret Manager reference, never the raw value).

## 7. CI/CD with GitHub Actions

The idea: instead of running all those commands by hand, **push code → it builds and deploys itself.**

The pipeline lives in `.github/workflows/deploy.yml` and does exactly what you did manually: checkout → build image → push to Artifact Registry → deploy to Cloud Run.

To run it on your own fork later, first create a robot account (a **service account**) for GitHub with only the permissions it needs:

```powershell
# PowerShell
gcloud iam service-accounts create gha-deployer --display-name "GitHub Actions deployer"
$SA = "gha-deployer@$PROJECT.iam.gserviceaccount.com"
foreach ($ROLE in "roles/run.developer", "roles/artifactregistry.writer", "roles/iam.serviceAccountUser") {
  gcloud projects add-iam-policy-binding $PROJECT --member="serviceAccount:$SA" --role=$ROLE --condition=None
}
gcloud iam service-accounts keys create gha-key.json --iam-account=$SA
```

```bash
# bash
gcloud iam service-accounts create gha-deployer --display-name "GitHub Actions deployer"
SA="gha-deployer@$PROJECT.iam.gserviceaccount.com"
for ROLE in roles/run.developer roles/artifactregistry.writer roles/iam.serviceAccountUser; do
  gcloud projects add-iam-policy-binding $PROJECT --member="serviceAccount:$SA" --role=$ROLE --condition=None
done
gcloud iam service-accounts keys create gha-key.json --iam-account=$SA
```

Then add these under **GitHub → Settings → Secrets and variables → Actions**:

| Secret | Value |
|---|---|
| `GCP_SA_KEY` | the entire contents of `gha-key.json` |
| `GCP_PROJECT_ID` | your project ID |
| `GCP_REGION` | `me-central1` |
| `CLOUD_RUN_SERVICE` | `meme-generator` |

> Delete `gha-key.json` from your laptop once it's in GitHub, and **never commit it** (it's a password for your project).

Then make a change, commit, and push:

```bash
git add .
git commit -m "Change page colour"
git push origin main
```

Watch it run in the **Actions** tab, then refresh your live URL. The change is there, and you never ran a deploy command. That's CI/CD.

## 8. Clean up (IMPORTANT: do this so you don't get billed)

One command deletes everything you created today:

```bash
gcloud projects delete $PROJECT --quiet
```

> This removes the registry, the Cloud Run service, the secret, and the GitHub robot account in one go. Check in the console under **IAM & Admin → Manage resources** that your project shows *Pending deletion*. Billing stops straight away.

Your Gemini key lives in AI Studio's own free project, so it costs nothing if you keep it. To delete it, go to **aistudio.google.com → API keys**.

## 9. Troubleshooting

| Problem | Likely cause | Fix |
|---|---|---|
| `docker build` can't connect | Docker Desktop not running | Start it; wait for the steady whale icon |
| `gcloud` not recognised | CLI just installed | Open a new terminal, re-paste your variables |
| `localhost:8080` won't load | wrong port mapping | use `-p 8080:8080` |
| Page says "AI not configured yet" | key not set | add `-e GEMINI_API_KEY=...` / attach the secret (step 6.3) |
| "AI call failed: ... valid API key" | wrong key or typo | re-copy the key from AI Studio |
| "AI call failed: ... 429" | free-tier rate limit | wait a minute and try again |
| `projects create` fails | ID taken / bad characters | lowercase letters, digits, hyphens; change the digits |
| "billing must be enabled" / "API not used in project" | billing not linked / APIs off | re-run the billing link and `services enable` commands |
| `docker push` → denied | Docker not linked to gcloud | re-run `gcloud auth configure-docker $REGION-docker.pkg.dev` |
| Deploy fails: "failed to start and listen on the port" | wrong port | use `--port 8080` |
| Logs show `exec format error` | built on an Apple Silicon Mac | rebuild with `--platform linux/amd64`, push, redeploy |
| "Permission denied on secret" | app can't read the secret | re-run the `add-iam-policy-binding` command in 6.2 |
| URL shows 403 Forbidden | service isn't public | redeploy with `--allow-unauthenticated` |

## 10. Quick command reference

```bash
# Setup
gcloud auth login
gcloud projects create $PROJECT
gcloud config set project $PROJECT
gcloud billing projects link $PROJECT --billing-account=<ACCOUNT_ID>
gcloud services enable run.googleapis.com artifactregistry.googleapis.com secretmanager.googleapis.com

# Containers
docker build -t ai-meme-generator:v1 .
docker run -d -p 8080:8080 ai-meme-generator:v1
docker ps / docker logs <id> / docker stop <id>

# Artifact Registry
gcloud artifacts repositories create $REPO --repository-format=docker --location=$REGION
gcloud auth configure-docker $REGION-docker.pkg.dev
docker tag ai-meme-generator:v1 $IMAGE_URI
docker push $IMAGE_URI

# Cloud Run
gcloud run deploy $SERVICE --image $IMAGE_URI --region $REGION --port 8080 --allow-unauthenticated
gcloud run services update $SERVICE --region $REGION --set-secrets "GEMINI_API_KEY=gemini-api-key:latest"
gcloud run services update $SERVICE --region $REGION --update-env-vars "MEME_STYLE=sarcastic"
gcloud run services logs read $SERVICE --region $REGION --limit 30

# Clean up
gcloud projects delete $PROJECT --quiet
```

**Nice work! You took an AI app from your laptop to a public cloud service, and never put a secret in your code.**
